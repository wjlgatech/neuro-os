    How to enable LLM mode

    The chat surfaces and the Living Knowledge brainstorm/interview use Anthropic to answer naturally. Without a key, they fall back to a state-machine that works but is stiffer (one field at a time, no creative help).

    1. Get a key at console.anthropic.com/settings/keys — create one starting with sk-ant-….

    2. Stop the daemon (Ctrl-C in the terminal where you ran neuro-os start).

    3. Export the key, then restart with --use-llm: 

    export ANTHROPIC_API_KEY=sk-ant-...
neuro-os start --use-llm

    The --use-llm flag is a separate consent gate: setting the key alone doesn't auto-route chat content through Claude. Without the flag, the daemon stays in state-machine fallback even with a valid key (this is so you don't accidentally burn API credits while testing).

    4. Refresh this page. The pill in the header should turn green and say LLM ready.

    To keep the key set across shell sessions, add the export line to your ~/.zshrc / ~/.bashrc / ~/.config/fish/config.fish. The MCP server (Claude Code, Cursor) reads from the same env var, so this one line enables both. If your key lives in a .env file, source it with set -a; source path/to/.env; set +a before starting the daemon — Python's os.environ doesn't auto-load .env.

    Why no in-app paste field? A POST endpoint that writes credentials to disk is a real attack surface even with CORS hardening. The env-var path keeps the daemon's HTTP surface credential-free.
